## 可量化验收标准

| 维度 | 目标 |
|------|------|
| **稳定性** | Windows 常驻运行 7×24h，连续 7 天无崩溃 |
| **CPU** | 全程平均 CPU ≤ 5%；高频切窗场景下无明显卡顿 |
| **内存** | 常驻内存 ≤ 300 MB |
| **查询延迟** | 1 天数据（≥10,000 事件/关键帧）时间轴查询与筛选 P95 ≤ 300ms |
| **数据完整性** | 窗口切换事件与截图关键帧落库成功率 ≥ 99.9% |
| **崩溃恢复** | 异常中断后重启可从 SQLite 状态机恢复分析进度（任务不丢、可重试、可标记失败） |

## 项目定位

TimeTrace 的核心价值是"**可回放的桌面行为时间轴**"，而不是录屏，也不是 AI 伴侣主体。

**第一优先级**：稳定采集 → 稳定存储 → 稳定回放 → 稳定搜索。VLM / 自动分类属于后置增强能力，避免在 Phase 1 把系统复杂度与外部依赖拉满。

### 核心特征

- **Windows Only**：使用 pywin32 访问 Windows 窗口 API
- **本地优先**：所有数据存储在本机，默认不上传
- **低打扰**：采集在后台静默运行，CPU/内存预算严格约束
- **可分发**：SQLite 单文件 + PyInstaller 打包，无需安装运行时

### 非目标

- 不是连续录屏工具
- 不是需要服务端部署的 SaaS
- 不是 AI 伴侣主体（只是上下文/工具入口）
- Phase 1 不做 VLM/Embedding（留给 Phase 1.5）

## 功能清单（全生命周期）

按"采集 → 存储 → 分析 → 检索/回放 → 对外接口"闭环组织：

| 模块 | 功能 |
|------|------|
| **采集** | 活跃窗口切换、窗口标题/进程/应用/URL、关键帧截图、键鼠计数、idle 段判定 |
| **存储** | SQLite 元数据；截图与缩略图本地文件夹；向量与索引（本地） |
| **分析** | VLM 描述、embedding、候选召回、分类决策、统计聚合 |
| **检索** | 时间范围/应用/分类过滤；文本相似搜索；（可选）以图搜图 |
| **回放** | 日历 + 单日时间轴、多轨道视图、hover 详情、点击进入记录详情 |
| **摘要** | 按时间段生成 summary（可缓存，不作为原始数据必存） |
| **分类** | 规则分类、模型分类、KNN 投票、置信度与 decision_trace |
| **隐私** | 黑名单、暂停记录、隐私模式、模糊/不存图策略、外部接口不返原图 |
| **MCP/API** | 时间段上下文、统计、检索工具、分类列表与 schema |
| **前端** | TimelineCanvas、详情面板、搜索页、设置页、反馈交互 |
