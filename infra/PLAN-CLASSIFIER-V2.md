## 出发点：做减法

当前分类决策是「规则/反馈 vs VLM」的加权投票（`server/rules/engine.py` 的 `SOURCE_WEIGHTS = user_edit 5 / user_confirm 3 / rule 2 / vlm 1.5` + confidence 比值）。KNN 近邻投票此前已删（依赖人工打标、噪声大）。

V2 的总基调是**先减后加**：把过度设计的加权投票数学拿掉，分类回归「默认纯 VLM」，只保留必要的确定性兜底。

---

## 三个方向（仅勾勒，不展开）

### ① 决策简化：默认纯 VLM + 一条确定性硬覆盖

- 删掉 5/3/2/1.5 加权与 confidence 比值。
- 默认：VLM 的分类直接生效。
- 仅保留一条**确定性硬覆盖**给「用户手动改过 / 明确指定」的项（硬保证，不走概率）。
- per-app 倾向交给提示词软引导（软约束，非硬保证）。

### ② KNN 当加速器（不是投票，是省 VLM）

- 经济动机：VLM 每帧约 11–18s（回填实测），多模态嵌入毫秒级。
- 用**本地多模态嵌入器 `qwen3-vl-embedding-2b`（视觉+文本混合，已部署在 box LMS）**对**图像**取向量；新帧若与已分类帧的向量足够近 → 复用其分类、跳过 VLM；够远 → 走 VLM。
- 可分层：pHash 近重复（已有 BK-tree）秒复用 → 图嵌入语义近 → 都远才 VLM。
- **阈值是关键、需校准**：嵌入距离怎么量、「多近算够近」要拿真实数据测分布定阈值（见下「待定」）。
- 已知风险：缓存投毒——种子帧标错则近邻全继承错标 → 阈值须保守 + 依赖③能失效重算。

### ③ 纠错分层

- **人↔agent 聊天纠错**：聊天中指出「这标错了，重标」→ 触发重分类。单条改的 `apply_label` MCP 写工具已实装。
- **批量 reset + 重打分**：改分类器提示词/分类选项后，对匹配某关键词/正则的记录重新入队重分类——复用今晚回填用的同一套「重新入队 pending_vlm」机制。
- **agent 自我纠错 / 「梦游模式」**：定时（如每日）自底向上反思、清扫记忆——这与金字塔线的 nightly rollup + 信号检测是同一件事，接到那条线上，不单独造。
