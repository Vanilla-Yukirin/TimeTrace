# Agent 活动读取契约：最新活动、分级摘要与稳定分页

时间：2026-10-22 21:47。本文为提交前的开发快照。

## 问题与范围

消费端把按时间升序返回的第一页当成最新活动，忽略后续游标，从而把分页末尾与当前时间之间的距离解释为用户不在线。读取接口需要明确区分最新采集、客户端联系、处理进度和分页覆盖。

本次只调整 TimeTrace 的 Agent/MCP 读取接口、内部 Agent 路由提示和仓库中的接入说明。不修改外部消费端，不部署，不改生产数据，也不读取原始截图。

## 实现

- `get_latest_activity`：按设备直接取最新记录，附设备描述、最近联系、服务端接收时间、采集年龄和分析状态。未上报的设备、历史无设备记录和未来时钟分别表达；在线状态始终为未知，不能从缺记录推断离线。
- `get_activity_overview`：按设备优先选已闭合且叙述完成的粗粒度摘要，缺失部分回退到细粒度，不重复返回父子窗口。明确返回实际粒度、截断、未覆盖区间、待处理和未闭合窗口，不在读取时调用模型。
- `get_recent_activity`：保留默认升序，增加显式降序；使用时间戳与 ID 的复合排序，返回 `has_more`、页边界和固定时间窗。不透明游标冻结首次查询的时间范围与记录行号高水位，后续插入不混入翻页；兼容旧记录 ID 游标。
- `search_summaries`：继续作为精确粒度查询和下钻入口，补充窗口可用性、覆盖范围、数量和截断提示；按重叠窗口查询，避免漏掉覆盖查询区间的粗粒度摘要。
- 内部 Agent 和 MCP 共用实现与参数；仓库中的接入 Skill 同步说明，不向外部消费端安装或分发。

## 边界

概览采用查看时区的自然日，最多 31 个自然日，夏令时切换不按固定毫秒天数裁切。原有统计与精确摘要工具保留既有逻辑日语义；需要严格对齐时传显式起止时间。

分页高水位不是跨请求数据库事务快照；已有记录的分析结果仍可更新，维护或删除数据后应重新开始分页。精确摘要搜索的 `has_more` 提醒调用方缩小范围，不声称提供分页游标。

覆盖数仅统计记录时间落在返回窗口中的数量，不证明摘要已反映迟到记录或语义正确。缺记录、空描述、摘要未生成和未返回的下一页都不能解释为用户离线。
