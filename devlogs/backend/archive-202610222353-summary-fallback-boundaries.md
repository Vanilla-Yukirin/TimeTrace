# PR 23 复审：摘要退路保持原请求边界

2026-10-22。基线 `8a3d9cc` 三项 CI 已通过；云端 Codex 评审额度仍阻塞。本次自主复查并处理复审评论的跨窗问题，未合并、未部署，未调整外部消费端。

## 根因与选择

概览按自然日零点确定范围，存储摘要的 day/week 按逻辑日切分。直接对原范围做 overlap 搜索，会带回包含凌晨部分的上一日/周整窗叙述。

仅让退路使用相同命名 period 会改变问题的时间含义：凌晨 4 点前的 today、周一凌晨的 this_week、月初凌晨的 this_month 仍可能对应上一逻辑时段；查看时区与存储时区不同也会造成边界不齐。因此保留原绝对范围，显式约束摘要必须完整位于范围内。

## 改动

- `search_summaries(window_match="contained")` 只保留完整位于请求范围内的窗口；默认 overlap 保持兼容。
- 所有返回窗口增加 `extends_outside_period`，提醒调用方不能把越界整段叙述当成本时段事实。
- 全局退路返回可直接传入的 arguments，固定原 custom 起止和 contained。粗层无可用窗口或有缺口时保持范围下钻；仅使用 ready 窗口，不重复计入已覆盖部分，仍无摘要时读取原始记录。设备指定查询保持设备过滤。
- 全文与短词检索在 SQL LIMIT 之前完成边界过滤，避免越界命中占满限额而隐藏合法结果；普通列表在截断前过滤。
- 同步内部 Agent、MCP、仓库接入说明。非阻塞的“概览截断保留最早窗口”维持原有显式语义，不在此轮扩大改动。

## 验证

新增 11 项参数化回归：普通读取/全文/LIKE × 全局/设备共六种路径，及今天、周一、月初凌晨/日间五个边界场景。用真实临时 SQLite 重现旧 overlap 返回上一逻辑窗，并验证 contained 排除它、细粒度仍能找到原时段叙述。MCP/内部 dispatch 连通测试增加新参数。
